[HOW TO USE]
  1. Choose a buffer, function or full shader from the Example menu.
  2. For a function, change numeric inputs and step through the calculation.
  3. For Raymarch, pick a pixel and follow its samples, values and code.
  4. Inspect input offsets, padding and field order in the data layout.


[RULES]
Constant buffers use DXC legacy 16-byte rows. Arrays and structures start on rows, but a following value may reuse the last row of an aggregate. Array stride and occupied extent are distinct.
Structured elements use component alignment and structure tail padding. These are DirectX DXC rules, not Vulkan std140/std430 or a CPU ABI.


[PRECISION]
bool occupies 4 bytes. half occupies 4 bytes by default, or 2 with native 16-bit mode. Minimum-precision values in default mode occupy 4 bytes and cannot share cbuffer rows with fixed-precision types.
Changing a numeric value does not change its typed storage size.


[SCOPE]
The repeated budget multiplies the rounded layout span. API resource alignment, descriptors, upload heaps, VRAM allocation, registers, execution time and CPU/GPU transfers are outside this model.
Input layout follows documented packing rules. Function and raymarch examples predict fixed calculations with ideal float32 arithmetic. A function result needs drawing context to become a screen pixel. The browser does not compile arbitrary HLSL or capture GPU execution.


[LIMITS]
32 KiB declarations; 128 fields per structure; nesting depth 8; literal array lengths 1–4096; 1 MiB layout and 16384 scalar components. Map pages show 16 rows. No source is executed or uploaded.
