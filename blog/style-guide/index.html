Atlas article style guide

This page is the visual source of truth for technical articles. Every example below uses the production classes loaded by the blog rather than a disconnected mock component.

$ compose_article --system atlas --content technical_rnd _

01 Principles

The notebook is an engineering record, not a product landing page. Layout, hierarchy, and decoration must help a reader inspect implementation details quickly.

DOUse flat beige paper, visible structure, real media, concise labels, and restrained blue interaction accents.
AVOIDGradients, rounded cards, marketing claims, decorative animation, cropped technical images, and invented project data.

02 Design tokens

Use variables instead of introducing isolated color or spacing values. Content emphasis uses ink and semantic status colors; interactive controls use Commander blue.

TokenRoleUse on
--atlas-accent #0000AAInteraction onlyButtons, focus, selected navigation, link hover
--atlas-crit #8B0000Content riskBreaking changes, errors, critical callouts
--atlas-ok / --atlas-warnSemantic statusValidated results and caution notes
--atlas-inkContentHeadings, body and labels — never replace with blue
--atlas-bg#E6DCD2
--atlas-bg-raised#EEE7DF

--atlas-accent#0000AA

--atlas-warn#8A5B14

Spacing rhythm: 4 / 8 / 12 / 16 / 22 / 32 / 56 px. Borders remain one pixel. Corners remain square.

03 Typography

JetBrains Mono is used for interface, metadata, headings, code, and body copy. Editorial serif is reserved for homepage prose and does not enter technical article records.

H1 shellDocument title
H2Content section heading
H3Content subsection
BodyImplementation, constraints, decisions and results — short paragraphs, concrete nouns.
MetaVERSION · PLATFORM · STATUS
InlineUse RenderGraph.Execute() for identifiers.

04 Section structure and lists

Each article moves from context to implementation and evidence. Use semantic H2 sections and H3 subsections; the article shell generates its left navigation from them.

  • Problem or production context
  • Constraints and assumptions
    • Target hardware
    • Performance budget
  • Implementation and validation
  • 01Context and constraints
  • —Target hardware

Use .atlas-section-break only between major conceptual groups, not after every heading.

05 Callouts

Callouts carry semantic information. Never use them as decorative cards.

Neutral implementation note or definition.

Critical limitation, breaking change, or production risk.

Caution about performance, compatibility, or destructive operations.

Validated result, completed check, or confirmed production state.

Attributed external principle or concise reference point.

06 Code, math, and comparison

Code samples require a language label, enough surrounding explanation to establish intent, and no screenshots of source code.

// HLSL — use a real, minimal production fragment
float3 ApplyExposure(float3 color, float exposure)
{
    return color * exp2(exposure);
}
\[ t_{frame} = \frac{1000}{f_{target}} \; \text{ms} \]
\[ L_o(p, \omega_o) = \int_{\Omega} f_r(p, \omega_i, \omega_o)\,L_i(p, \omega_i)\,(n \cdot \omega_i)\,d\omega_i \]

Comparison matrix — use for two competing approaches, before/after states, or done/in-progress status. Use a data table instead when values have units or must be compared row by row.

Δ1 // STATIC TEXTURE
Locked resolution · fixed response · high VRAM footprint.
Δ2 // PROCEDURAL SYSTEM
Runtime control · field-aware response · ALU-bound generation.

07 Data tables and diagrams

Tables are for exact comparisons and measured data. Keep headings short and units explicit. Diagrams explain topology, ownership, flow, or spatial relationships that prose cannot scan quickly.

[ PERFORMANCE_BUDGET // MEASURED_DATA ]
TargetBudgetValidation
Desktop VR11.1 msGPU capture
Mobile XR13.8 msDevice profile

Architecture diagram — use nodes and arrows for data flow or ownership. Keep one reading direction, label every scope, and highlight only an actual risk or critical execution layer.

// DATA_FLOW // AUTHORING → RUNTIME
SOURCE
Houdini / DCC
VALIDATE
Schema / budget
RUNTIME
Unity / Unreal

Geometric schematic — draw as inline SVG with a responsive viewBox. Use design tokens for strokes, dashed lines for secondary volumes, direct labels plus a text legend, and never rely on color alone.

08 Media and galleries

Technical media uses object-fit: contain. Captions explain what evidence the reader should inspect.

Interactive embed — use only when interaction is evidence. Provide a title, lazy loading, a fixed minimum height, and a fallback link or explanation.

LIVE_SHADER_PREVIEW
WebGL / iframe component boundary

09 Actions and references

Use filled blue only for the primary action. The quiet white dither action is the default for index navigation and supporting links: visible as part of the interface, but subordinate to the article. Bracket buttons are compact secondary commands.

11 Article authoring contract

The canonical machine-readable instructions live beside the content. Future LLM sessions should read that file before drafting or converting an article.

Required orderContext → constraints → implementation → evidence → result → references.

Required assetsDescriptive alt text, local repository paths, captions, and contain-based presentation.

Required shellShared article navigation, registry entry, metadata, previous/next links, and local footer.

ForbiddenInvented results, unsupported claims, gradients, rounded product cards, and Wix-only URLs.
